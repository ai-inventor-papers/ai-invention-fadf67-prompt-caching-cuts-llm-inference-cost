## Full Summary

Pure-Python analytical simulation comparing four KV-cache reuse strategies for LLM serving (monolithic prefix caching, chunk-level caching, speculative approximate reuse, cache-optimal prompt restructuring) across five synthetic workloads (high sharing, partial overlap, similar-but-mutated prefixes, variable component order, wide-overlap), using a shared 7B-class transformer cost model (L=32, D=4096, H=32; prefill FLOPs = L*(n^2*d + n*4d^2); KV = 512 KiB/token fp16) with seeded LRU+TTL eviction. All strategies run on identical request streams under an identical cost model, so comparisons are controlled. method_out.json (exp_gen_sol_out schema, 55 examples; one per experiment cell with predict_monolithic / predict_chunk / predict_speculative / predict_restructure fields holding each strategy's full metrics) contains the main 4x4 grid (1000 requests/cell, seed 42), an 8-point memory-budget sweep (200K-50M KV tokens), a tau x n-gram x correction-fraction sensitivity sweep for speculative reuse, and a wide-overlap crossover analysis. Headline findings: (1) chunk-level caching matches or beats monolithic prefix caching on every workload (99.8% prefill-FLOP savings on partial overlap, 99.9% on variable order) while using 36-500x less KV memory; (2) monolithic caching only survives when whole prefixes repeat: on a wide-overlap workload (C(12,4)=495 subset space) it collapses to 3.2% savings while chunk reuse stays at 99.5% - the regime that motivates chunk-granular serving systems; (3) n-gram (n=4,8) Jaccard matching is structurally useless for 5-15% token mutation (pairwise Jaccard ~0.3-0.5 falls below any useful threshold), while token-set matching (n=1) at tau=0.70 recovers 74.3% prefill savings where exact caches give exactly 0% - a negative result about the plan's original n=8/tau=0.85 design discovered by smoke-test failure; (4) speculative reuse never beats exact caches when exact reuse is possible (correction-pass overhead costs ~10 points on high_sharing); (5) results are stable across seeds 42-45 (std of savings <= 2.2 points on every cell). Deliverables also include seed_robustness.json, three publication figures (PDF+PNG), a validated cost-model sanity-check script, and full/mini/preview variants of the schema output. Runtime ~5.7 min single-threaded on 2 CPUs.
